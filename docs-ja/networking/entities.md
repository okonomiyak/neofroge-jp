# エンティティ {#entities}

通常のネットワークメッセージのほかにも、エンティティのデータの同期を扱うためのさまざまな仕組みが用意されています。

## スポーン時のデータ {#spawn-data}

1.20.2 以降、Mojang はバンドルパケットという考え方を導入しました。これは、エンティティのスポーンパケットをまとめて送るために使われます。これにより、スポーンパケットとともにより多くのデータを、より効率的に送れるようになりました。

次のインターフェースを実装すると、NeoForge が送るスポーンパケットに追加のデータを加えられます。

### IEntityWithComplexSpawn

エンティティに、クライアントで必要だが時間とともに変化しないデータがある場合は、このインターフェースを使ってエンティティのスポーンパケットに追加できます。`#writeSpawnData` と `#readSpawnData` で、データをネットワークバッファにどうエンコード・デコードするかを制御します。あるいは、エンティティの初期データがクライアントに送られるときに呼ばれる `IEntityExtension#sendPairingData` メソッドをオーバーライドすることもできます。このメソッドはサーバーで呼ばれ、スポーンパケットと同じバンドル内で、追加のペイロードをクライアントに送るのに使えます。

## 動的データパラメータ {#dynamic-data-parameters}

これは、エンティティのデータをサーバーからクライアントに同期するための、バニラの主要な仕組みです。そのため、参考にできるバニラの例が多数あります。

まず、同期し続けたいデータ用の `EntityDataAccessor<T>` が必要です。これはエンティティのクラスに `static final` フィールドとして保存してください。エンティティのクラスと、そのデータ型用のシリアライザを渡して `SynchedEntityData#defineId` を呼び出すと取得できます。利用できるシリアライザの実装は、`EntityDataSerializers` クラスに static 定数として用意されています。

:::caution
データパラメータは、自分のエンティティについて、_そのエンティティのクラス内で_ __のみ__ 作成してください。自分が管理していないエンティティにパラメータを追加すると、データをネットワーク経由で送るために使う ID がずれて同期しなくなり、デバッグの難しいクラッシュの原因になります。
:::

次に、`Entity#defineSynchedData` をオーバーライドし、データパラメータごとに、パラメータと初期値を渡して `SynchedEntityData.Builder#define` を呼び出します。必ず最初に `super` メソッドを呼び出すことを忘れないでください!

これで、エンティティの `entityData` インスタンスを通じて、これらの値を取得・設定できます。加えた変更は自動でクライアントに同期されます。
