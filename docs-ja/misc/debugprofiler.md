# デバッグプロファイラ {#debug-profiler}

Minecraft にはデバッグプロファイラがあり、時間のかかっているコードを見つけるために、システムのデータ、現在のゲーム設定、JVM のデータ、レベルのデータ、Side ごとの tick の情報を提供します。`TickEvent` や tick 処理を行う `BlockEntities` などを考えると、ラグの原因を探したい Mod 開発者やサーバーの管理者にとって、これは非常に役立ちます。

## デバッグプロファイラの使い方 {#using-the-debug-profiler}

デバッグプロファイラの使い方はとても簡単です。プロファイラを開始するには、デバッグ用のキーバインド `F3 + L` を使います。10 秒後に自動で停止しますが、もう一度キーを押せば早めに止めることもできます。

:::note
当然ながら、プロファイルできるのは実際に実行されるコードの経路だけです。プロファイルしたい `Entities` や `BlockEntities` を結果に表示させるには、それらがレベルに存在している必要があります。
:::

デバッガを止めると、実行ディレクトリの `debug/profiling` サブディレクトリに、新しい zip ファイルが作成されます。
ファイル名は、日付と時刻を使って `yyyy-mm-dd_hh_mi_ss-WorldName-VersionNumber.zip` の形式になります。

## プロファイル結果の読み方 {#reading-a-profiling-result}

Side ごとのフォルダ( `client` と `server` )の中に、結果のデータを含む `profiling.txt` ファイルがあります。先頭には、まず実行時間( ミリ秒 )と、その間に実行された tick の数が記載されています。

その下には、次の抜粋のような情報があります。

```
[00] levels - 96.70%/96.70%
[01] |   Level Name - 99.76%/96.47%
[02] |   |   tick - 99.31%/95.81%
[03] |   |   |   entities - 47.72%/45.72%
[04] |   |   |   |   regular - 98.32%/44.95%
[04] |   |   |   |   blockEntities - 0.90%/0.41%
[05] |   |   |   |   |   unspecified - 64.26%/0.26%
[05] |   |   |   |   |   minecraft:furnace - 33.35%/0.14%
[05] |   |   |   |   |   minecraft:chest - 2.39%/0.01%
```

各部分の意味を簡単に説明します。

| [02]                     | tick                    | 99.31%       | 95.81%       |
| :----------------------- | :---------------------- | :----------- | :----------- |
| セクションの深さ | セクションの名前 | 親に対してかかった時間の割合。階層 0 では、1 tick にかかる時間に対する割合です。階層 1 では、親にかかる時間に対する割合です。 | 2 つ目の割合は、tick 全体のうちどれだけの時間がかかったかを示します。

## 自分のコードのプロファイル {#profiling-your-own-code}

デバッグプロファイラは、`Entity` と `BlockEntity` を基本的にサポートしています。それ以外のものをプロファイルしたい場合は、次のように手動でセクションを作る必要があるかもしれません。

```java
ProfilerFiller#push(yourSectionName : String);
//The code you want to profile
ProfilerFiller#pop();
```
`ProfilerFiller` のインスタンスは、`Level`、`MinecraftServer`、`Minecraft` のインスタンスから取得できます。
あとは、結果のファイルで自分のセクション名を探すだけです。
